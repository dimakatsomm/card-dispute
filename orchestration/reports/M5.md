# M5 — Back office (ADR-071): milestone report

**Verdict: MET locally, 2026-11-04.** Integration-verifier ran against a freshly rebuilt and reseeded local stack. The dev rollout (BO-09) is owner-gated and outside this close.

## What shipped
A human agent signs in to the SPA on the dedicated `backoffice` client, sees the review queue across customers (oldest first), opens a dispute, picks it up (SUBMITTED → UNDER_REVIEW) and resolves it (ACCEPTED / REJECTED with a customer-visible note).

Every write:
- runs under `SELECT … FOR UPDATE`;
- checks `expectedVersion` and `expectedEvidenceDigest` (412 when stale) and returns 409 on an invalid transition;
- is recorded as `actor_type AGENT` with `actor_id` = agentId and `actor_label` = the agent's display name;
- emails the customer through the existing notifier.

Customers and agents are refused on each other's routes, and the customer's timeline only ever shows `BANK`.

## Evidence
- **Static checks:** `pnpm typecheck`, `lint`, `lint:api` (7 specs) and `check:contracts` all pass; the frontend production build passes.
- **Unit and integration:** `pnpm test` passed **1,437 tests across 17 packages, 0 failed** (disputes 256, auth 127, auth-client 89, frontend 123, seed 99, mock-issuer 30, …).
- **e2e:** `pnpm test:e2e` gave 47 passed, 9 failed, 1 skipped.
  - m5 (back office) 15/15 and m1 22/22.
  - All 9 failures are in m2 and each needs the Lambda containers: evidence-intake, the scan stub, and the retention-sweeper RIE.
- **Playwright:** agent-flow and customer-flow pass. The three evidence-status specs (M2) fail for the same Lambda reason.
- **Independent walkthrough:** 50 of 51 checks passed; the one miss was a bug in the verifier's script. It confirmed:
  - **Queue:** paging, filtering, and no customer identifiers.
  - **Writes:** stale version, bad digest and short note are refused; pick-up replay works; resolve replay keeps the first note; the other outcome gets 409.
  - **Database:** history rows `REVIEW|…|AGENT|<agentId>|Naledi M.`, and `disputes_app` cannot UPDATE history.
  - **Customer and mail:** the customer view is BANK-only with the note, and mail goes to the owner only.
  - **Route separation:** wrong-principal requests get 403, the disabled agent 401, and an agent signed in on `spa` 401.
  - **UI:** a scratch Playwright spec covered the 412 reload and the customer/agent area separation.
- **Gates:** every task passed security, tests and standards before commit. The design had adversarial review 02, with accepted fixes folded in.

## Covered by tests vs not
- **Covered:** all M5 acceptance criteria (see the gate reports); the withdraw-vs-resolve race in both directions (deterministic); fail-closed on DB errors and on a missing or invalid displayName; the backstop's path and opt-in rules, including prefixed plugins and encoded paths (probed against real Fastify).
- **Not covered here:**
  - The real Lambda images: the proxy blocks the Lambda base image, so the notifier ran its real handler in a stand-in container rather than under the RIE.
  - Real Cognito, i.e. `cognito:groups` on a real access token. This is documented AWS behaviour, verified only via search results.
  - The dev rollout and AWS-side behaviour.
  - The expired-token e2e, which needs `MOCK_ISSUER_TEST_HOOKS`.

## Deferred, and why
- **BO-09, dev rollout:** owner-gated. It covers the Cognito group and `backoffice` client, the ALB `/agent/*` rule, `AUTH_AGENT_CLIENT_IDS` and the web OIDC_AGENT_* variables, agent provisioning with TOTP, the offboarding runbook, and the SES sandbox finding.
- **Evidence viewing for agents:** out of scope by owner ruling. BO-09 is labelled demo-only.
- **BO-H1:** backstop hardening (top-level param routes; `/health` and `/ready` exempt for all methods). Not exploitable today.
- **BO-H2 (new):** the auth test teardown race. On an unhandled pool error (`57P01`), auth exits 1 although 127/127 passed. Seen once in a full run; auth alone passed 3 out of 3.
- **BO-H3 (new):** the contracts generator still adds its own code-point length check, which is redundant with zod 4.6. Harmless; the comment is corrected.

## Known gaps and risks
- **Deploy order (high):** auth fails fast without `AUTH_AGENT_CLIENT_IDS`, and dev's Terraform does not set it yet. Approving an auth deploy to dev before BO-09 will break auth there.
- **Agent MFA:** MFA is per user and set at provisioning, and Cognito access tokens do not prove MFA was used. Real data needs a separate pool with MFA required.
- **Agent access off-switch:** disabling an agent takes up to 60 s (the auth-client cache); removing the group takes up to 15 min (the token lifetime). The offboarding runbook (BO-09) disables the row first.
- **CI:** the image builds depended on `get.trivy.dev`, which went down. Fixed by installing a SHA-pinned release from GitHub (9eced5d); the pin must be bumped by hand.
